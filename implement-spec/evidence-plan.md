# Acceptance evidence plans

After an independent reviewer provides semantic judgments, run `python3 <skill-dir>/scripts/acceptance_evidence.py --input <manifest.json> --output <plan.json>` to check correspondence. The command prints a summary and the plan path; read full sources from their original paths as needed. It leaves tracker access, write-back, and formal report validation to their established interfaces.

The input contains `ticket` (full identity), `commit` (candidate), `criteria` (each criterion's `id`, exact `text`, and `proofs` IDs), `proofs`, and `review`. Criterion and proof IDs are unique. Each proof contains `id`, `path`, `sha256`, `commitPointer`, `statusPointer` (JSON Pointers into the original report), and `sources` (original file paths and hashes). The report must actually be `passed` and match the commit. Use the project's existing validator to establish internal report completeness. Text and binary sources receive hash checks without JSON parsing.

`review` points to the saved independent report through `path` and `sha256`. That report contains `reviewer`, `implementer`, `commit`, and `criteria`; each judgment includes exact `text`, `decision:earned`, `reason`, and `locations`. The tool checks declared relationships. The coordinator verifies the reviewer's actual independence and reasoning; an implementer-authored report cannot substitute for review.

Reusing older evidence requires explicit `reuse` with `originalCommit`, `targetCommit`, and `source`. That source JSON preserves `originalCommit`, `targetCommit`, `unchanged:true`, `scope` (criterion IDs), and the actual content-comparison basis. Confirm that the evidence still matches the current scope. A project's same-commit formal acceptance rule takes precedence over this generic reuse mechanism. Preserve original report sources, execution identity, and completion time.

The output lists sources, gaps, exact criteria, and `proposedCheckboxes`, with `written:false` throughout. Complete materials still require independent semantic judgment. Before write-back, follow [acceptance](acceptance.md): reread current criteria, match exactly, check authorization, and verify the actual write result.
